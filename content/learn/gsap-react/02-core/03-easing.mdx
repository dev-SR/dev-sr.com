## Default feel

UI entrances and exits should use **`ease-out`** (`power2.out`, `power3.out`) — they start fast and settle, so the user sees motion immediately.

## `ease-in` on UI

<ComponentPreview replay>
  <GsapEaseInVsOut />

  <DocsFileTabs title="Ease in vs out">

```tsx title="ease-in-vs-out.tsx"
// ✓ Responsive — power2.out
gsap.fromTo('.dropdown', { y: -8, autoAlpha: 0, scale: 0.97 }, { y: 0, autoAlpha: 1, scale: 1, ease: 'power2.out' });

// ✗ Sluggish — power2.in delays the moment users watch
gsap.fromTo('.dropdown', { y: -8, autoAlpha: 0, scale: 0.97 }, { y: 0, autoAlpha: 1, scale: 1, ease: 'power2.in' });
```

```html title="ease-in-vs-out-markup.html"
<div class="flex gap-8">
  <div class="gsap-dropdown-out w-36 rounded-lg border bg-card p-3">Feels responsive</div>
  <div class="gsap-dropdown-in w-36 rounded-lg border bg-card p-3">Feels sluggish</div>
</div>
```

  </DocsFileTabs>
</ComponentPreview>

<Callout variant="dont" title="Never ease-in on UI">
  `ease-in` starts slow. On a 200ms dropdown, the important frame is late — it feels unresponsive even at the same duration.
</Callout>
