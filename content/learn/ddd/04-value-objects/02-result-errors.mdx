---
title: 'Result errors'
description: 'Make success and failure explicit at the domain boundary.'
---

## Shape

```csharp
Result<Customer> customer = Customer.FindById(id);
if (!customer.IsSuccess)
    return MapError(customer); // NotFound / Validation / Conflict
```

## Why it helps

- Callers cannot ignore failure as easily as a nullable return
- Error **type** maps cleanly to HTTP without parsing exception messages
- Domain methods stay expressive: `Reserve()` returns `Result<Equipment>`

Still throw for programmer errors (null where null is illegal inside a private invariant you already guarded).
