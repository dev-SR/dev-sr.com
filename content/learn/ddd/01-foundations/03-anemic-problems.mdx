## What goes wrong

1. **Dumb entities** — no language for “reserve,” only `Available = false`
2. **Logic in services** — every feature opens the same god class
3. **Scattered rules** — date checks here, fee math there, availability elsewhere
4. **Invalid states** — `new Rental { EndDate = start.AddDays(-1) }` compiles
5. **No invariants** — construction never validates
6. **Leaky abstraction** — callers must know field choreography
7. **Weak ubiquitous language** — code talks in DTO field names
8. **Harder tests** — must mock the whole service graph to assert one rule
9. **Expensive change** — one rule touch ripples across services and controllers

Refactoring plan (next chapters):

1. Move logic into entities
2. Enforce invariants at construction and in workflows
3. Replace setters with behavior
